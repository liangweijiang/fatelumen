# 4. 八个位置基础权重

建议不要认为八个字力量一样。

初始：

| 位置 | Weight |
| -- | -----: |
| 年干 |   0.85 |
| 月干 |   1.15 |
| 日干 |   1.00 |
| 时干 |   0.95 |
| 年支 |   1.00 |
| 月支 |   1.80 |
| 日支 |   1.35 |
| 时支 |   1.05 |

核心原则：

```text
月支最高
日支第二重要
月干较重要
其余参与全局
```

例如：

```text
月支寅
```

内部贡献不是：

```text
Wood += 1
```

而是：

```text
甲木 = 1.80 × 0.70
丙火 = 1.80 × 0.20
戊土 = 1.80 × 0.10
```

得到：

```text
Wood += 1.26
Fire += 0.36
Earth += 0.18
```

# 5. 月令绝对不能重复计算

这里必须规定清楚。

月支拥有：

```text
PositionWeight = 1.80
```

然后所有五行再统一乘：

```text
SeasonCoefficient
```

禁止：

```text
月支算一次超大权重
+
得令再额外重复加几十分
+
月令藏干再次特殊加分
```

否则月令会被重复计算三四遍。

所以：

```text
月令位置权重
```

代表：

> 月支这个位置的重要性。

而：

```text
SeasonCoefficient
```

代表：

> 整个季节对五行的环境影响。

二者含义不同。

# 6. 旺相休囚死基础模型

定义五档：

```text
旺 = 1.60
相 = 1.30
休 = 0.90
囚 = 0.65
死 = 0.45
```

这套数值为工程参数。

传统关系：

```text
当令者 = 旺
当令者所生 = 相
生当令者 = 休
克当令者 = 囚
被当令者所克 = 死
```

例如春木：

```text

水 休
金 囚
土 死
```

夏火：

```text
火 旺
土 相
木 休
水 囚
金 死
```

秋金：

```text
金 旺
水 相
土 休
火 囚
木 死
```

冬水：

```text
水 旺
木 相
金 休
土 囚
火 死
```

土旺月份另做处理。

# 8. 节气连续修正

同样是寅月：

```text
立春刚过
```

和：

```text
惊蛰前一天
```

五行环境不能完全相同。

因此计算：

```text
SeasonProgress =
DaysSinceCurrentJie /
DaysBetweenCurrentAndNextJie
```

得到：

```text
0 ~ 1
```

下一月系数为 `NextCoefficient`。

最终：

```text
SeasonCoefficient =
CurrentCoefficient × (1 - P)
+
NextCoefficient × P
```

例如：

```text
寅月木 = 1.55
卯月木 = 1.65

P = 0.60

WoodSeason =
1.55 × 0.40
+
1.65 × 0.60

= 1.61
```

这样月令变化就是连续的。

# 11. 天干透出奖励

地支藏干如果同时透出同类天干：

例如：

```text
寅藏甲
天干又见甲
```

意味着：

```text
木气透出
```

建议：

```text
透干奖励 +5% ~ +15%
```

根据：

```text
是否同柱
是否月令
是否有根
透几个
```

建议：

```text
普通透干 1.05
同柱透根 1.08
月令透干 1.12
月令本气透干 1.15
```

上限：

```text
1.20
```

防止重复放大。

# 12. 根气计算

根属于：

```text
日主生命力
```

特别重要。

定义：

```text
RootPower(DM)
```

日主五行在四地支藏干中出现即有根。

但分：

```text
强根
中根
弱根
```

例如甲木：

```text
寅甲 = 强根
卯乙 = 强根
亥甲 = 中根
辰乙 = 弱根
未乙 = 弱根
```

不要直接：

```text
看到木 = 根
```

而应：

```text
RootPower =
BranchWeight
× HiddenRatio
× SeasonCoefficient
× RootQuality
```

# 19. 生不是凭空增加总能量

这是数学模型非常重要的一点。

例如：

```text
木生火
```

不能：

```text
木不变
火 +20
```

否则系统总能量无限膨胀。

采用：

```text
Transfer Model
```

木的一部分有效力量：

```text
Wood - Transfer
Fire + Transfer × Efficiency
```

例如：

```text
TransferRate = 0.12
Efficiency = 0.85
```

# 26. 合化判断

```text

```

```text

化神是否透出
```



```text

```


# 36. 身强弱核心公式

设：

```text
P = 比劫有效力量
R = 印星有效力量
O = 食伤有效力量
W = 财有效力量
K = 官杀有效力量
```

支持：

```text
Support =
P × 1.00
+
R × 0.85
```

压力：

```text
Pressure =
O × 0.70
+
W × 0.75
+
K × 0.95
```

为什么权重不同：

```text
官杀 = 直接克身
财 = 日主主动消耗
食伤 = 日主泄气
印 = 生身但不是日主自身
比劫 = 最直接同类力量
```

# 94. 完整主算法

```typescript
function analyzeBazi(chart: RawChart): BaziAnalysis {

    // 1
    const pillars =
        parsePillars(chart);

    // 2
    const hidden =
        expandHiddenStems(pillars);

    // 3
    const season =
        analyzeSeason(chart, pillars);

    // 4
    const rawPower =
        calculateRawPower(
            pillars,
            hidden
        );

    // 5
    const seasonalPower =
        applySeason(
            rawPower,
            season
        );

    // 6
    const roots =
        analyzeRoots(
            pillars,
            hidden,
            season
        );

    // 7
    const combinations =
        detectCombinations(pillars);

    const clashes =
        detectClashes(pillars);

    // 8
    const transformations =
        evaluateTransformations(
            combinations,
            seasonalPower,
            roots
        );

    // 9
    const effectivePower =
        calculateEffectivePower({
            seasonalPower,
            combinations,
            clashes,
            transformations,
            roots
        });
```

# 95. 喜用神完整算法

```typescript
function deriveUsefulGod(
    ctx: UsefulGodContext
): UsefulGodResult {

    if (ctx.pattern.isConfirmedSpecial) {
        return deriveSpecialPatternUsefulGod(ctx);
    }

    const fuYi =
        analyzeFuYi(ctx);

    const disease =
        analyzeDiseaseMedicine(ctx);

    const climate =
        analyzeClimateNeed(ctx);

    const pattern =
        analyzePatternNeed(ctx);

    const passThrough =
        analyzePassThrough(ctx);

    const flow =
        analyzeFlowNeed(ctx);

    const candidates = [];

    for (const element of ELEMENTS) {

        const staticScore =
            scoreCandidate(
                element,
                {
                    fuYi,
                    disease,
                    climate,
                    pattern,
                    passThrough,
                    flow
                }
            );

        const simulated =
            simulateElementIncrease(
                ctx,
                element
            );

        const sideEffects =
            evaluateSideEffects(
                ctx,
                simulated
            );

        const validation =
            hardValidateCandidate(
                element,
                ctx,
                simulated
            );

        candidates.push({
            element,
            score:
                staticScore
                + simulated.marginalUtility
                - sideEffects,

            valid:
                validation.valid,

            reasons:
                validation.reasons
        });
    }

    const ranked =
        rankCandidates(candidates);

    const primary =
        selectPrimary(ranked, ctx);

    const secondary =
        selectSecondary(
            ranked,
            primary,
            ctx
        );

    return classifyElements(
        ctx,
        ranked,
        primary,
        secondary
    );
}
```

# 108. 最终数学思想

真正重要的不是：

```text
火是不是喜神？
```

而是定义当前命局状态：

```text
S
```

然后模拟：

```text
S木 = F(S + Δ木)
S火 = F(S + Δ火)
S土 = F(S + Δ土)
S金 = F(S + Δ金)
S水 = F(S + Δ水)
```

定义命局健康函数：

```text
H(S) =
W1 × StrengthBalance
+
W2 × ClimateBalance
+
W3 × PatternIntegrity
+
W4 × ElementFlow
+
W5 × DiseaseResolution
-
W6 × StructuralConflict
```

那么：

```text
Utility(木) = H(S木) - H(S)
Utility(火) = H(S火) - H(S)
Utility(土) = H(S土) - H(S)
Utility(金) = H(S金) - H(S)
Utility(水) = H(S水) - H(S)
```

经过：

```text
Hard Rule Validation
```

以后：

```text
Utility最高且解决PrimaryDisease的元素
=
第一用神
```

第二高且与第一用神协同：

```text
=
第二用神
```

正效用：

```text
=
喜神候选
```

强负效用：

```text
=
忌神
```

间接帮助忌神：

```text
=
仇神
```

接近零：

```text
=
闲神
```

```text
+

+

+
```


也不是：

```text

```


# 可解释的八字规则引擎

数学模型负责：

```text

```

规则追踪负责：

```text
告诉我们为什么得出这个结果。
```

这四层合起来，才是适合真正写进程序里的喜用神系统。
