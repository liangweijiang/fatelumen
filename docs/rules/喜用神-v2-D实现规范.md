# 喜用神 V2-D 实现规范

## 1. 版本与职责

规则版本：`useful-god-v1.1`。

候选元素 What-If 模拟的健康度与静态评分使用同一组动态权重。出现严重寒热、燥湿、病药或流通问题时，先按规则重分配权重，再以该组权重对基准状态和所有候选状态作同口径比较；原局可用性只参与静态可行性评分，不进入模拟健康度。

本模块严格消费五行力量 V2-B、身强身弱 V2、有效十神 V2 与 V2-C 的调候、格局、病药、通关结果。它是确定性计算器，不调用 LLM，也不允许使用“缺什么补什么”的查表逻辑。

## 2. 候选和权重

木、火、土、金、水永远全部参加计算。普通命局初始权重遵循原始规范：扶抑 25、病药 20、格局 20、调候 15、通关/流通 10、可用性 10。严重寒热、极强主病、明显流通阻塞时通过版本化 `RuleSet` 动态调整权重，其余权重按比例缩放。

## 3. What-If 重算

每个五行分别模拟 `+5/+10/+15/+20` 标准力量，默认排名使用接近 `+8` 的模拟点。每次模拟都会：

1. 从原四柱重新运行五行力量引擎；
2. 注入候选五行并重新运行两轮生克；
3. 重新计算身强弱；
4. 重新计算调候；
5. 重新计算病药；
6. 重新计算通关和流通；
7. 重新复核格局候选。

健康函数由强弱平衡、寒热、燥湿、格局完整度、流通和病神严重度组成，全部权重集中在规则集。边际效用为新状态健康分减去原状态健康分。

## 4. 硬否决和分类

严重恶化极端寒热、造成新的重大失衡或破坏已确认特殊格局时，候选标记为无效并进入忌神，不得成为用神或喜神。

第一用神必须同时满足：有效、总分最高、边际效用为正，并在存在主病时确实解决主病。第二用神要求正边际效用且与第一用神相生协同。其余元素根据总分、间接生助关系和结构语义划分为喜神、忌神、仇神或闲神。

## 5. 可追溯结果

每个候选保存：

- 静态评分分项；
- 四档模拟前后状态；
- 边际效用和副作用；
- 有效性与硬否决原因；
- 原局可用度；
- 近似最佳范围；
- 最终角色和置信度。

完整结果写入 `ChartData.useful_god`、`InterpretationFacts.useful_god` 和 `favorable_elements`，规则版本进入事实版本与 `facts_hash`。

## 6. 当前校准边界

原始规范给出了评分框架和权重，但未给出健康函数内部各项权重、原局可用度的根气/保护精确系数和全部特殊格局顺势矩阵。当前数值集中于版本化规则集并输出待校准警告；后续修改不改变接口、快照或报告链路。
