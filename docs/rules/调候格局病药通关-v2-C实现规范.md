# 调候、格局、病药与通关 V2-C 实现规范

## 1. 模块与版本

- 调候：`climate-v1.0`
- 格局复核：`pattern-review-v1.0`
- 病药：`disease-v1.0`
- 通关：`mediation-v1.0`

四个模块均为独立确定性计算器，业务编排只依赖输入输出契约。规则常数集中在各模块 `RuleSet`，后续调整阈值或增加规则不需要修改命盘主流程。

## 2. 调候

月令基础温度严格使用原始规范第 52 节的十二支初值，输出 `Temperature` 与 `Moisture`，范围均为 `[-100,100]`。严重度采用原始规范第 54 节：绝对值小于 40 为普通、40 至 70 为明显、大于 70 为严重。

原始规范没有给出全局水火修正和十二支湿度的精确数表。当前工程初值全部封装于 `RuleSet`，输出 `climate_global_adjustment_coefficients_require_domain_calibration`，用于提示管理端该部分仍需命理规则校准。

## 3. 格局复核

复用身强身弱 V2 的从格、专旺、化气候选及其否决证据，不重复计算。普通格局与组合结构消费有效十神的正偏证据；例如官印相生和杀印相生分别要求正官、七杀的具体证据，不能只凭官杀类别总量同时命中。

结果区分 `candidate` 与 `rejected`。被否决的候选仍保留，方便管理端追查，但不得成为主格局。当前存在阈值仍是集中式工程初值，并输出待校准警告。

## 4. 病药

识别日主强弱、五类十神过旺、寒热燥湿及五行对峙。病项按严重度排序，输出主病、次病和轻微病。严格遵守“缺五行不等于病”，不会因为某五行为零直接生成病项。

病药模块当前只输出候选改善方向，不生成最终喜用神。

## 5. 通关

实现五种固定通关关系：金克木取水、木克土取火、土克水取金、水克火取木、火克金取土。双方均超过最低冲突力量且比例处于 `0.60..1.67` 才视为对峙，再区分通关五行已存在、不足或缺失。

原始规范未给出 `MinimumConflictPower` 和通关充足阈值，当前规则集采用可替换工程初值并输出待校准警告。

## 6. 快照与边界

- 四个结果写入 `ChartData`，同时进入 `InterpretationFacts`。
- 四个规则版本进入版本对象和 `facts_hash`。
- `chart-snapshot-v2` 与 `interpretation-facts-v2` 标识新增契约；旧快照仍可按其历史版本读取。
- 本阶段不输出最终喜用神、不调用 LLM、不生成报告正文。
