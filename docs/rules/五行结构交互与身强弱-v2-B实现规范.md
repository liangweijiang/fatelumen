# 五行结构交互与身强身弱 V2-B 实现规范

## 1. 版本与职责

- 五行结构交互：`bazi-power-v2.0`
- 身强身弱：`strength-v2.0`
- 有效十神：`ten-god-effective-v2.0`

原始输入规范保存于 `八字五行力量身强身弱与喜用神算法-v2.0-原始稿.md`。本阶段只实现确定性前置计算，不计算最终喜用神，也不调用 LLM。

## 2. 结构交互流水线

1. 先完成 V2-A 原始力量、季节修正和第一轮生克。
2. 按三会、三合、半合、天干合、六合、冲、刑、害、破的顺序处理结构证据。
3. 三合完整命中时抑制其重复半合；重叠结构仍逐条留下命中证据和调整记录。
4. 合化置信度综合结构类型、月令支持、目标五行占比、透干、根气、克制与争合因素，输出完整合化、部分合化或合而不化。
5. 冲按双方强弱决定留存率；刑、害、破只调整可用性；墓库本阶段只保留证据，不额外创造能量。
6. 结构调整后进行第二轮半系数生克，输出最终有效五行力量。

十二长生随命盘保存并进入结构证据，但原始规范未提供可复核的精确加减表，因此 V2-B 暂按中性系数 `1.00` 记录，不擅自引入经验常数。

## 3. 身强身弱 V2

基础分：

```text
Support = 比劫 × 1.00 + 印星 × 0.85
Pressure = 食伤 × 0.70 + 财星 × 0.75 + 官杀 × 0.95
Base = 100 × (Support - Pressure) / (Support + Pressure)
Final = Base × 0.70 + 得令 × 0.10 + 得地 × 0.12 + 得势 × 0.08
```

最终分数限定为 `[-100, 100]`，划分极弱、弱、偏弱、平衡、偏强、强、极强七档。输出同时保存得令、得地、得势、置信度、逐项追踪和从格/专旺/化格候选；候选只表示进入后续格局复核，不能直接视为成格。

## 4. 有效十神 V2

有效十神由最终五行力量分配，但正偏阴阳比例只能复用原始显干、藏干证据，不允许从聚合五行反推。若某类有效五行有力量、原始命盘却没有该类阴阳证据，则该部分保留为未分配力量，不凭空均分正偏十神。

## 5. 快照和兼容

- 系统运行时只允许当前规则输出一套正式身强弱结论；`strength.level/score` 与当前完整计算明细必须一致。
- `strength.analysis` 中的位置、藏干和关系贡献属于最终计算的上游依据，不是另一套身强弱结论。
- `strength_v2` 是当前阶段遗留的计算明细字段名，不代表运行时存在两套可选算法；后续 Schema 收敛时并入正式 `strength`。
- 已完成报告的快照不可回写；读取历史快照时允许兼容旧字段，但不得让旧摘要覆盖报告实际采用的当前结论。
- 规则版本进入事实版本对象和 `facts_hash`，版本号用于解释报告生成当时的规则，不代表运行时同时启用多个算法版本。
- 管理端可通过报告基础数据详情查看输入、结构证据、计算轨迹及版本。

## 6. 后续边界

V2-C 再实现调候、格局、病药与通关。最终喜用神必须消费这些完整确定性结果，当前阶段不得直接生成。
