## 1. 使用规则

1. 本文档是完整报告建设的唯一执行进度台账；需求定义仍以上述两份权威规范为准。
2. 每个任务只允许使用四种状态：`未开始`、`进行中`、`待验收`、`已完成`。
3. 已存在部分代码但未满足全部验收条件的任务只能标记为`进行中`。
4. 标记`已完成`必须同时记录：实现范围、测试命令与结果、提交号、完成日期。
5. 每次开始工作前先读取本台账；每次完成小块后先更新台账，再向用户汇报下一步。
6. 完成记录只追加、不覆盖；需求调整必须在“决策与范围变更”中留下日期和原因。
7. 未经用户明确要求，不自动提交或推送；提交后必须把提交号补入完成记录。

### 2026-09-02：R1.3 校验失败自动追加 attempt

- 单章重试：格式、Schema、完整度、确定性事实、语言术语或产品边界校验失败时，在冻结的 `max_attempts` 内自动追加attempt；每次输入、原始输出和校验结果独立保存。
- 汇总重试：十章汇总校验失败后读取 `affected_chapters`，只把仍有尝试额度的受影响章节恢复为待生成；其他成功章节不重跑。失败汇总轮次和旧attempt保持不可变、可查询。
- 状态衔接：汇总校验在 `assembling` 保存失败轮次，自动重试时回到 `generating`，受影响章节成功后再次进入 `assembling`；额度耗尽或不可重试错误使整份报告失败。
- 验证：Docker内 `go test ./internal/repository ./internal/service ./internal/llm/prompts` 通过；Docker内 `go build ./...` 通过。
