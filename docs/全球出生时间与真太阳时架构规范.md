# FateLumen 全球出生时间、真太阳时与共享排盘引擎规范

> 状态：已确认，后续实现必须遵循
> 适用范围：免费排盘接口、完整报告接口及其共用的确定性排盘核心
> 上位约束：`docs/FateLumen-开发任务书.md`、P1（排盘只使用 `lunar-go`）

## 1. 已固定的产品决策

1. 用户输入的是出生地点当时钟表记录的**当地民用日期时间**，不是 UTC，也不是北京时间。
2. 系统根据地点确定 IANA Timezone ID，用户不手工填写 UTC Offset、DST、标准经线、均时差或真太阳时。
3. 全球出生时间不统一转换为北京时间排盘；北京时间只适用于其法定时区场景。
4. 默认排盘时间模式为 `TRUE_SOLAR_TIME`。
5. 默认换日规则为 `MIDNIGHT_00`：以最终真太阳时的 00:00 换日，对应 `lunar-go v1.4.6` 的 `EightChar sect=2`。
6. 免费排盘必须登录，不扣积分、不设置每日次数；接口应配置合理的防刷频率限制。
7. 免费排盘不创建完整报告、不进入报告列表、不保存出生档案；为登录用户保存独立排盘历史，支持分页查询、详情、单条删除和批量删除。
8. 免费排盘前端、完整报告前端相互独立；两个 API、请求 DTO、响应 DTO 也相互独立。
9. 两个 API 必须调用同一个 `BirthChartEngine`，共用真太阳时、换日、`lunar-go` 计算和 `chart_hash` 缓存。
10. 免费排盘结果只是统一命盘结果的字段裁剪，不存在第二套排盘算法或命盘模型。

## 2. 用户输入语义

核心输入：

```text
calendar_type
birth_local_date
birth_local_time
is_leap_month（农历时使用）
gender
birth_location 或 latitude + longitude
```

`birth_local_date + birth_local_time` 表示出生地当时的当地民用时间（Local Civil Time）。系统负责地点标准化、历史时区、DST、UTC、当地标准时间、平太阳时、均时差和真太阳时。

地点规则：

- 国家/地区有值：解析出明确地点、经纬度与 IANA Timezone ID。
- 经纬度有值：反向解析国家、地区、城市与 IANA Timezone ID。
- 两组都有：全部保存、全部展示，以经纬度作为太阳时间计算依据。
- 两组明显不匹配：拒绝计算并要求用户重新确认。
- 两组都没有：拒绝计算。

正式地点候选必须至少细化到城市或可唯一定位的地点。仅有国家、省或州不足以可靠确定经度。

## 3. 唯一计算流程

```text
用户输入当地民用日期时间与出生地点
        │
        ▼
BirthInputNormalizer
  ├─ 日期、时间、性别校验
  ├─ 公历输入直接标准化
  └─ 农历输入（含闰月）先转换成对应公历日期
        │
        ▼
LocationResolver
  ├─ country / region / city
  ├─ latitude / longitude
  └─ IANA timezone_id
        │
        ▼
HistoricalTimezoneResolver
  ├─ historical_utc_offset
  ├─ standard_utc_offset
  ├─ dst_applied / dst_offset
  ├─ birth_utc_datetime
  └─ local_standard_datetime
        │
        ▼
SolarTimeEngine
  ├─ standard_meridian
  ├─ longitude_correction
  ├─ mean_solar_datetime
  ├─ equation_of_time
  └─ true_solar_datetime
        │
        ▼
BaziRuleEngine
  ├─ TRUE_SOLAR_TIME
  └─ MIDNIGHT_00
        │
        ▼
LunarGoCalculator
  └─ 四柱、五行、十神、藏干、纳音及其他确定性命盘数据
        │
        ▼
统一 BirthChartResult + chart_hash
        ├─ FreeChartResponse（字段裁剪）
        └─ 完整报告后续流程
```

顺序不得改变：必须先得到真太阳时及其自然跨日结果，再应用八字换日规则，最后调用 `lunar-go`。

## 4. 农历输入处理

农历输入必须先完成闰月校验并转换为对应的当地公历日期，再进入历史时区与真太阳时流程：

```text
农历日期 + 当地民用时间
→ 对应公历日期 + 当地民用时间
→ 历史时区 / DST
→ 真太阳时（可能跨日）
→ lunar-go 排盘
```

禁止在原始农历日期上先排盘、再单独修正时柱。

## 5. 模块架构

```text
FreeChartHandler ──► FreeChartService ─┐
                                      ├─► BirthChartEngine
ReportHandler ─────► ReportService ───┘       ├─ BirthInputNormalizer
                                              ├─ LocationResolver
                                              ├─ HistoricalTimezoneResolver
                                              ├─ SolarTimeEngine
                                              ├─ BaziRuleEngine
                                              ├─ LunarGoCalculator
                                              └─ ChartRepository
```

接口层只负责认证、DTO 映射、业务权限和响应裁剪。任何 handler/service 都不得自行实现时区修正、真太阳时或四柱计算。

### 5.1 BirthChartEngine

```go
type BirthChartEngine interface {
    Calculate(ctx context.Context, input BirthChartInput) (*BirthChartResult, error)
}
```

相同输入、规则版本、时区数据库版本和计算器版本必须返回相同结果。

### 5.2 BirthInputNormalizer

负责输入校验、公农历标准化与农历转公历，不负责地点、时区、太阳时间或四柱。

### 5.3 LocationResolver

```go
type LocationResolver interface {
    Search(ctx context.Context, keyword, locale string) ([]LocationCandidate, error)
    Resolve(ctx context.Context, input LocationInput) (*ResolvedLocation, error)
}
```

具体地理服务通过 `cmd/server/main.go` 注入，业务层只依赖接口。

### 5.4 HistoricalTimezoneResolver

根据 `local_civil_datetime + timezone_id` 查询出生当时的历史规则，区分总 UTC Offset、标准 UTC Offset 与 DST Offset。必须识别夏令时切换造成的不存在时间和重复时间，不能静默猜测。

### 5.5 SolarTimeEngine

```go
type SolarTimeEngine interface {
    Calculate(input SolarTimeInput) (*SolarTimeResult, error)
}
```

该模块只计算太阳时间，不包含年柱、月柱、日柱、时柱或其他命理规则。

### 5.6 BaziRuleEngine 与 LunarGoCalculator

`BaziRuleEngine` 选择最终排盘时间和换日规则；`LunarGoCalculator` 只接收已经确定的排盘日期时间并调用 `lunar-go`。禁止在 `LunarGoCalculator` 内查询网络、地点或时区。

## 6. 真太阳时公式

```text
local_standard_datetime
= local_civil_datetime - dst_offset

standard_meridian
= standard_utc_offset_hours × 15°

longitude_correction_minutes
= (longitude - standard_meridian) × 4

mean_solar_datetime
= local_standard_datetime + longitude_correction_minutes

true_solar_datetime
= mean_solar_datetime + equation_of_time_minutes
```

标准经线必须使用剔除 DST 后的标准 UTC Offset。禁止将 DST 后的临时 Offset 用于标准经线，也禁止将 `120°E` 写死为全球基准。

均时差采用可替换的独立算法实现。首版可使用已确认的常用太阳位置近似公式，但必须正确处理闰年、日期边界、秒级时间和浮点精度，并记录算法版本。

## 7. 换日规则

默认固定：

```text
time_calculation_mode = TRUE_SOLAR_TIME
day_boundary_rule = MIDNIGHT_00
lunar_go_eight_char_sect = 2
```

处理顺序：

1. 当地民用时间转换为真太阳时。
2. 应用真太阳时产生的自然日期变化。
3. 以真太阳时 00:00 作为日界。
4. 将最终日期时间交给 `lunar-go`。

架构保留 `LATE_ZI_23`（对应 `sect=1`）用于内部对拍或未来规则扩展，但未经新的产品决策不得向普通用户开放或改变默认值。

## 8. 免费排盘与完整报告边界

| 层级 | 免费排盘 | 完整报告 |
|---|---|---|
| 前端页面/组件 | 独立 | 独立 |
| API | 独立 | 独立 |
| 请求/响应 DTO | 独立 | 独立 |
| 登录 | 必须 | 必须 |
| 积分 | 不扣 | 按报告规则 |
| 每日次数 | 不限制，仅防刷 | 按报告规则 |
| 保存档案 | 不保存 | 按档案联动规则 |
| 创建报告 | 不创建 | 创建 |
| 独立排盘历史 | 保存，支持查询与删除 | 不适用 |
| `BirthChartEngine` | 共用 | 共用 |
| `chart_hash` 与缓存 | 共用 | 共用 |

建议接口边界：

```text
POST /api/v1/free-charts              → 创建免费排盘历史并返回 FreeChartResponse
GET /api/v1/free-charts               → 分页查询当前用户历史
GET /api/v1/free-charts/:id           → 查询当前用户详情
DELETE /api/v1/free-charts/:id        → 删除当前用户历史
POST /api/v1/free-charts/batch-delete → 批量删除当前用户历史（最多 100 条）
POST /api/v1/readings/full → 完整报告任务
```

路径最终以第 5 章 API 契约为准。免费接口只能裁剪统一命盘结果，不得复制核心计算逻辑。

## 9. 数据与可追溯性

内部至少保存或可重建：

```text
原始当地民用日期时间、原始地点输入
country / region / city / place_id
latitude / longitude / timezone_id
historical_utc_offset / standard_utc_offset
dst_applied / dst_offset
birth_utc_datetime / local_standard_datetime
standard_meridian / longitude_correction_minutes
mean_solar_datetime / equation_of_time_minutes
true_solar_datetime
time_calculation_mode / day_boundary_rule
最终传给 lunar-go 的日期时间
地点数据源版本、时区数据库版本、太阳时间算法版本、lunar-go 版本
```

用户隐私不得写入普通日志；日志只记录 `trace_id`、`chart_hash`、算法版本和脱敏错误摘要。

## 10. chart_hash

`chart_hash` 必须覆盖所有影响命盘的标准化值：

```text
gender
calendar_type + 原始日期时间 + is_leap_month
latitude + longitude + timezone_id
historical_utc_offset
time_calculation_mode + day_boundary_rule
地点解析版本 + 时区数据库版本
太阳时间算法版本 + lunar-go 版本
```

任一规则或算法版本改变，都必须产生新的哈希，禁止复用旧命盘。

## 11. 结果展示

免费排盘结果只展示完整命盘数据中产品批准开放的字段，不额外暴露内部计算数据。

地点展示规则：

- 国家/地区有值则展示国家/地区。
- 经纬度有值则展示经纬度。
- 两组都有则全部展示。

输入校验规则：国家/地区和经纬度可以任选一组；两组同时提交时，必须由地点数据源反查经纬度所属的国家及一级行政区并与选择项一致。冲突时拒绝排盘；地点数据源未配置或暂时不可用时必须失败关闭，提示用户只提交其中一组，禁止跳过一致性校验继续排盘。

历史时区、DST、平太阳时、均时差、真太阳时及换日依据默认只保存在内部核验链，不作为免费结果的普通字段；管理或开发核验工具可按权限读取。

### 11.1 固定国家与城市基础数据

国家和城市使用一次性导入的 GeoNames 固定快照，不在运行时同步更新。仅保存国家四语名称，以及城市 GeoNames ID、国家、一级行政区、四语名称、WGS84 经纬度和 IANA 时区。中国地点必须有真实中文别名才可进入候选库，禁止用英文回填 `name_zh`，中国一级行政区统一使用中文名称。选择国家与城市时由后端城市记录提供经纬度；用户直接填写经纬度时不反推国家和城市。

免费排盘与完整报告录入页均展示可校正的出生记录时区。城市决定默认 IANA 时区，中国大陆默认 `Asia/Shanghai`；用户明确知道出生记录采用其他钟表标准时可修改。后端以固定城市记录的经纬度为准，并使用用户最终确认且合法的时区恢复出生钟表时间；手填经纬度时必须同时提供时区。时区用于恢复民用时间，经度用于标准经线与真太阳时修正，两者不得互相替代。

只读接口：

- `GET /api/v1/geo/countries?q=&locale=&page=&page_size=`
- `GET /api/v1/geo/cities?country_code=&q=&locale=&page=&page_size=`
- `GET /api/v1/geo/cities/:id`

## 12. 必须覆盖的测试

1. 中国大陆非 DST 场景及经度修正。
2. 美国夏令时与非夏令时场景。
3. 历史 UTC Offset 发生变化的地点与年份。
4. 东西经、正负 Offset 和半小时/四十五分钟时区。
5. 真太阳时修正后跨日、跨月、跨年。
6. 真太阳时 22:59、23:00、23:59、00:00、00:01 的换日边界。
7. 农历闰月输入、农历转公历后再跨日。
8. DST 不存在时间与重复时间。
9. 地址与经纬度一致、冲突、缺失。
10. 免费接口与完整报告接口对相同输入得到相同 `chart_hash` 和四柱。
11. 已知命例与权威工具对拍。
12. 同一输入重复计算结果稳定且命中缓存。
